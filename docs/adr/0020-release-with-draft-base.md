# 0020. Выпуск 1.0 с медицинской базой в черновиках

**Решили.** «Анамнез» — отступление от правила устава «В выпуск идёт только проверенное»
([`docs/06-content.md` устава, «Проверка»](https://github.com/Nefeste/gornitsa/blob/main/docs/06-content.md#проверка);
ADR студии [0012](https://github.com/Nefeste/gornitsa/blob/main/adr/0012-content-sources.md)): 1.0.0 и следующие версии
выходят с медицинской базой в `review: draft` — без сверки по источникам и без проверки врачом-консультантом. Решения
владельца: 20.10.2026 в [#101](https://github.com/Nefeste/anamnez/issues/101), вопрос 7, — «Медицинскую проверку базы
разрешаю не делать»; 30.10.2026 в [#159](https://github.com/Nefeste/anamnez/issues/159), вопрос 48, — «вариант 1»:
записать отступление этой запиской. Устав разрешает ADR проекта отступать от правила студии с разрешения владельца
(`README.md` устава, «Старшинство правил»).

Остальное из правила устава остаётся: агент пишет записи `review: draft` с источником, отметку `checked` или `reviewed`
ставит только человек. На 30.10.2026 все 1026 медицинских записей базы 83 — состояния, признаки, обследования и
лечение — `draft`.

**Что проверено вместо сверки.**

- Источники — названные и первичные (ADR [0008](0008-content-sources.md), `11-content.md` §2). Клинические рекомендации
  Минздрава сверены с рубрикатором (`bun tools/content/clinrecs.ts`, 30.10.2026): все 94 действуют, названия совпадают,
  новых версий нет.
- Сборка и валидатор базы (`npm run content`) и её тесты: поля записей, связи между ними, причина у каждого признака
  (ADR [0009](0009-noisy-or-model.md)), лечение — группы и МНН без доз (ADR [0012](0012-inn-no-doses.md)).
- «Виртуальный врач» (`npm run doctor`, пороги — `11-content.md` §6) и модели больниц: разумный врач распознаёт болезни
  по признакам и обследованиям базы.

**Почему.**

- Консультанта у проекта нет (вопрос 7): по правилу устава 1.0 не вышла бы, пока его нет.
- «Анамнез» — игра, а не справочник и не средство самодиагностики. Что сведения упрощены и служат игре, говорят
  оговорки на первом запуске, в энциклопедии, в «Об игре» и в карточке магазина (`12-publishing.md` §3).
- Ошибки базы находят игроки — отзывами RuStore и письмами на support@gornitsa.games (вопрос 6,
  [#100](https://github.com/Nefeste/anamnez/issues/100)); исправление выходит новой версией записи (ADR
  [0011](0011-eternal-ids.md)).

**Платим.**

- В базе могут остаться неточности, которые заметил бы врач: частоты признаков, пороги, выбор лечения. Игрок без
  медицинского образования может запомнить неточное как правду — оговорки это смягчают, но не отменяют.
- Правило студии в проекте не выполняется: при переходе между проектами это нужно знать.
- `draft` — честная метка, а не фильтр: сборка берёт все записи при любом `review` (`11-content.md` §7).

**Когда пересмотреть.** Когда у проекта появится врач-консультант: первыми он сверяет состояния с `severity: critical`
и с красными флагами — до `reviewed`, как требовала приёмка 9. Раньше — если отзывы покажут систематическую ошибку в
отделении. Дополнения после 1.0 — педиатрия, акушерство, психиатрия — идут каждое со своей спецификацией и с
консультантом (`07-roadmap.md`, «Что сознательно после 1.0»).
