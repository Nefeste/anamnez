# 0001. Начинаем с нуля в новом репозитории; от предшественников — только идеи

**Решили.** Не продолжать ни `Nefeste/clinicsim-doctor-mode`, ни `Nefeste/ClinicSim`.
Новый проект — репозиторий `anamnez` со стеком и процессом «Вотчины». Из прошлых
прототипов переносятся только идеи (список ниже); ни строки кода и ни одной записи
данных.

**Что было (аудит 26.09.2026).**

`clinicsim-doctor-mode` — веб-приложение, сгенерированное Dyad (6 коммитов за вечер
16.11.2025): Vite, React 18, React Router, shadcn/ui, Tailwind, деплой на Vercel.

- Семь экранов (меню, быстрая игра, кампания, справочник, профиль, достижения,
  настройки) открываются без ошибок, но это макеты: пациенты, статистика профиля,
  прогресс кампании и достижения зашиты прямо в экраны.
- Игровой движок `src/lib/gameManager.ts` не подключён ни к одному экрану.
  «Завершить лечение» в быстрой игре всегда засчитывает успех и +150 к бюджету.
- В движке ошибка: эффективность лечения (уже доля от 0 до 1) ещё раз делится на 100 —
  успех около 1 %.
- Восемь болезней; все симптомы видны сразу, «исследование» — отметить галочками уже
  показанные; «отвлекающие» симптомы выбираются случайно из общего списка.
- Весь случай — `Math.random`, воспроизвести ничего нельзя; сохранений нет.
- Рядом лежат `app.js` и `index.html` — ещё одна, ванильная версия того же, и заготовки
  Godot-скриптов в `.txt`.
- CI — шаблоны GitHub «NodeJS with Grunt» и «with Webpack», к проекту не относятся и
  упали бы.
- Звука нет — есть переключатель «Sound Effects» без кода; картинок нет — иконки lucide.

`ClinicSim` — Godot 4.5, один коммит (ноябрь 2025), тег `alpha`.

- 29 болезней на русском: у симптома есть вероятность и список обследований, которые
  его открывают, — **форма модели правильная**, её идея переходит в noisy-OR
  (ADR [0009](0009-noisy-or-model.md)).
- Но состав и порядок болезней (свиной и бычий цепень, ветряная оспа, опоясывающий
  лишай, онихомикоз, дерматофития стопы, железодефицитная анемия, непереносимость
  лактозы…, серия «ушибов» руки, кисти, стопы, лодыжки, голени, груди) и обследование
  «ICU blood analysis» совпадают с базой Project Hospital. Переносить эти данные нельзя
  (ADR [0008](0008-content-sources.md)).
- Интерфейс собирается кодом из `Label` и `CheckBox`; в репозитории лежат собранный APK
  на 28 МБ и три копии сцен «backup».

**Почему с нуля.**

- **Переносить нечего, кроме идей.** Из кода прототипов в мобильной игре не выживет
  ничего: другой платформенный слой (веб или Godot против React Native), движка по
  сути нет, данные либо игрушечные, либо чужие.
- **Главная сложность проекта — модель и база**, а ни в одном прототипе нет ни
  детерминизма, ни проверки базы, ни честной генерации признаков. Их проще заложить
  с первого коммита, чем вкручивать в макеты.
- **Готовый путь в магазины уже есть** — у «Вотчины»: CI без EAS, подпись, RuStore по
  API, материалы магазинов, процесс SDD. Проще начать в нём, чем перестраивать прототип.
- **Чистая история.** В новом репозитории нет ни чужих данных, ни APK в git, ни
  автогенерированного мусора; права на всё содержимое понятны.

**Что берём из прототипов — только идеи.**

- Меню: быстрая игра, кампания, достижения, профиль врача, настройки, справочник.
- Поток случая: обследование → диагноз → лечение.
- Уровни кампании с целями (принять N, точность ≥ X, заработать Y), лимитом времени и
  стартовым бюджетом.
- Специализации врача, открываемые с уровнем; категории достижений (вехи, точность,
  скорость, деньги).
- Признак с вероятностью и обследованиями, которые его открывают.
- Настройки звука, музыки, скорости анимации, уведомлений.

**Платим.**

- Всё начинается с документов и прототипов-проверок; первое, во что можно поиграть, —
  через этап 1 (`10-roadmap.md`).
- Прототипы остаются в своих репозиториях как история; ссылок на их код в новом
  проекте нет.
