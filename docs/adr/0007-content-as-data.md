# 0007. Медицинская база — данные в YAML, собранные в один JSON, а не код

**Решили.** Исходник базы — файлы YAML в `content/`, по файлу на запись
(`05-content.md` §3). Скрипт `tools/content/build.ts` проверяет схему и ссылки,
переводит полосы в числа, вычисляет производное («с чем спутать») и собирает
`src/content/generated/bundle.json` с номером `contentVersion`. Собранный файл в
репозитории не хранится — его собирают `prestart`, `pretest` и CI.

**Почему.**

- **Объём.** Около 120 болезней, 500 признаков и тысячи связей к 1.0. В TypeScript
  (как `tiles/base.ts` «Вотчины») тысячи записей с объединёнными типами идентификаторов
  замедляют проверку типов, а ошибка в одной записи ломает сборку всего приложения.
- **Читатель — не только программист.** Запись YAML может сверить владелец и прочитать
  врач-консультант; комментарии разрешены, diff по файлу болезни понятен.
- **Проверки богаче типов.** Валидатор проверяет то, чего не выразить типом: у признака
  есть открывающее обследование, у болезни — достижимое подтверждение, две болезни
  различимы (`05-content.md` §6).
- **Одна база — все потребители.** Игра, энциклопедия, «виртуальный врач» и тесты
  читают один собранный файл.

**Платим.**

- Ещё один шаг сборки; забыл пересобрать — старая база (поэтому `prestart`/`pretest`).
- Ошибки в YAML видны при сборке базы, а не в редакторе кода; частично спасает JSON
  Schema, сгенерированная из схемы, — редактор подсказывает поля.
- Загрузка базы при запуске — разбор JSON в пару мегабайт; бюджет — 300 мс на среднем
  телефоне (NFR-PRF-2), при превышении — разбивка по отделениям с ленивой загрузкой.
