# Как устроено

Одно приложение на телефоне, без сервера (ADR [0006](adr/0006-offline-no-internet.md)).
Стек — Expo / React Native / TypeScript, как у «Вотчины»; карта и все изображения —
Skia (ADR [0002](adr/0002-expo-react-native-skia.md)). Пока кода нет, документ описывает
принятый проект; по мере появления кода он становится описанием кода.

## 1. Схема

```
  телефон: одно приложение, сети нет
┌─────────────────────────────────────────────────────────────────┐
│ app/  экраны (Expo Router): меню, кампания, игра, карта         │
│       пациента, энциклопедия, профиль, настройки                │
│          │ команды                     ▲ срезы «что знает игрок» │
│          ▼                             │                         │
│ src/state/session  живая партия: цикл времени, журнал команд,   │
│                    автосохранение                                │
│          │                             ▲ события                 │
│          ▼                             │                         │
│ src/engine  ДВИЖОК — med, hospital, sim, economy, career         │
│             чистый TypeScript, детерминированный, без платформы  │
│          ▲                                                       │
│ src/content  собранная база (JSON)  ◄── content/*.yaml (сборка)  │
│                                                                  │
│ src/render  Skia: карта, снимки, ЭКГ, портреты                   │
│ src/audio   звуки, вибрация                                      │
│ src/state/storage  файлы: сохранения, профиль, настройки         │
└─────────────────────────────────────────────────────────────────┘
  tools/ (Bun): тесты движка, сборка и проверка базы, «виртуальный врач»,
                сценарии Playwright по веб-сборке, снимки для магазинов
```

## 2. Главная мысль: движок — отдельно, всё остальное — отображение

Вся игра — это **состояние партии** (`GameState`, обычный сериализуемый объект) и
**движок**, который меняет его двумя способами:

- `apply(state, command)` — действие игрока: вопрос, осмотр, назначение, диагноз,
  постройка, найм. Возвращает события («открыт признак», «списано 900 ₽») и цену в
  игровых минутах;
- `advance(state, seconds)` — течение времени: приходят пациенты, готовятся анализы,
  люди идут по коридорам, болезни развиваются.

Из этого следует почти вся архитектура:

- **Движок не знает про React, экраны и телефон.** Его гоняют тесты и «виртуальный
  врач» в Bun тысячи раз в минуту — тот же код, что в игре.
- **Интерфейс только читает срезы и шлёт команды.** Никакой игровой логики в экранах.
- **Сохранение — снимок состояния** (ADR [0010](adr/0010-snapshot-saves.md)). В отличие
  от «Вотчины», партия здесь — не список ходов: время течёт само, и переигрывать недели
  симуляции при каждом открытии было бы долго. Журнал команд хранится только за текущий
  день — для отчёта об ошибке и тестов (§8).

## 4. Время

Решение о модели времени — ADR [0005](adr/0005-action-time.md).

- **Игровое время** — целые секунды от начала партии. Сутки, смена, часы — производные.
- **Очередь событий.** Всё, что назначено на момент, — приход пациента, готовность
  анализа, конец операции, поломка — лежит в двоичной куче по времени. `advance`
  достаёт наступившие события и обрабатывает их по порядку (при равном времени —
  по номеру постановки, чтобы порядок был детерминированным).
- **Движение** считается шагом в одну игровую секунду: у каждого идущего человека —
  маршрут (список клеток) и время выхода; позиция — функция времени.
- **Цикл на карте** (`tick` в `src/state/session.ts`): реальное время × скорость
  (×1 = 60 игровых секунд в секунду) превращается в игровые секунды, которые отдаются
  `advance` порциями не больше минуты (чтобы кадр не зависал на ×4). Сейчас — четыре
  тика в секунду, пока экран смены на виду и в кабинете никого; ходы времени подряд
  журнал сливает в один. «Красный» пришёл или пациент вернулся с результатами — пауза.
- **В карте пациента** цикл стоит. Команда возвращает цену, сессия вызывает
  `advance(state, цена)` и показывает, что за это время случилось.
- **Фон.** Когда приложение уходит в фон, цикл останавливается и делается сохранение.
- **Ночь и дом.** Исход пациента, отпущенного домой, решается при закрытии приёма из ветви
  зерна `outcome:<пациент>`. Течение в своей палате (с 0.0.43, `src/engine/shift/ward.ts`) —
  так же: при поступлении и при смене лечения на обходе, из ветви `ward:<пациент>:<смена>`;
  ночь ничего не бросает, а где лежащий в своей болезни и какие у него витальные, считается
  по суткам в стационаре. Поэтому обход, итоги дня и повтор журнала дают одно и то же.

## 5. Детерминизм

Решение — ADR [0004](adr/0004-deterministic-engine.md). Одинаковые зерно, команды и версия
базы дают одинаковое состояние на телефоне (Hermes), в тестах (Bun) и в симуляторе.

- **Генератор** — маленький быстрый ГПСЧ с состоянием из 128 бит (семейство sfc32 или
  xoshiro128**), своя реализация в `core/rng.ts`, версия генератора в состоянии партии.
- **Ветви зерна.** У каждой подсистемы своя ветвь (`rng.fork('patients')`,
  `rng.fork('exam:' + orderId)`): добавление нового броска в одной подсистеме не
  сдвигает случайность в других, и золотые случаи не ломаются от несвязанной правки.
- **Вероятности в состоянии — целые** доли 1/10 000; жребий — сравнение целых.
- **В коде, который меняет состояние, — только `+ − × ÷` и сравнения.** `Math.exp`,
  `Math.log`, `Math.pow`, тригонометрия по стандарту языка приблизительны и могут
  отличаться в последнем знаке между движками. Где нужны — свои реализации в
  `core/math.ts`. По выводу (`med/infer.ts`) решают страховая песочницы (0.0.22) и нанятые
  врачи (0.0.32), а это меняет состояние, поэтому с 0.0.32 его логарифм — свой `log2` из
  `core/math.ts` (только `+ − × ÷`, ошибка порядка 1e-16); польза обследования, кроме
  того, сравнивается после округления (`policy.ts`, `quantize`).
- **Никаких `Date.now()` в движке.** Реальное время — только для подписи сохранения.
- **Порядок обхода** — массивы и отсортированные ключи, не порядок вставки в `Map`
  из разных источников.

## 6. Карта: отрисовка и ввод

Карта — один `Canvas` Skia из нескольких слоёв:

| Слой | Как рисуется | Когда перерисовывается |
|------|--------------|------------------------|
| пол, стены, двери | записанный рисунок (`SkPicture`): стена — полоса по середине стеновых клеток, пол по обе стороны, дверь — проём со створкой; прямоугольниками, подряд одного цвета — одним | только после стройки |
| мебель и аппараты | `Atlas`: одна текстура, одно обращение к GPU на все предметы; повёрнуты — спиной к стене, стул к столу (`orient.ts`) | после стройки и смены состояния аппарата |
| люди | два слоя `Atlas` с одной матрицей — тела и головы; позиция и поворот считаются на UI-потоке | каждый кадр, пока кто-то идёт |
| свет аппаратов, лампы над дверями | слой `Atlas` с рисунками «работает» и круги с ореолом; горит ли — ворклет по часам карты | каждый кадр, пока кто-то идёт |
| значки, выделение, призрак стройки | обычные элементы Skia; значки помещений — поверх, элементами RN | по событию |

- **Движок отдаёт маршруты, а не координаты каждого кадра.** Когда человек начинает
  идти, UI-поток получает его маршрут и время выхода; позицию на каждом кадре считает
  ворклет Reanimated из общего значения «игровые часы». Так через границу потоков
  идут редкие маршруты, а не шестьдесят массивов в секунду.
- **Текстура спрайтов собирается кодом при открытии карты**: предметы и фигурки — векторная
  геометрия из данных, растрируются в атлас под плотность экрана — полторы точки экрана на
  точку клетки, от 48 до 128 точек на клетку (`src/render/map/sprites.ts`); собранный атлас
  хранится и при следующем открытии не рисуется заново.
- **Живая карта (0.0.37, [`specs/2026-09-living-map.md`](specs/2026-09-living-map.md))**.
  - У каждого аппарата свой рисунок: поле `sprite` в базе — `ecg`, `analyzer`, `xray`.
  - Пациент на карте — с одеждой и волосами своего портрета: место на карте несёт `look` —
    номер тела и головы в атласе (`figures.ts`, без Skia).
  - Идущий повёрнут по ходу, стоящий — к столу или аппарату, сидящий — как стул. `Walkers`
    отдаёт поворот на каждой точке пути вместе с путём, ворклет берёт поворот отрезка или
    остановки.
  - Подписи помещений — кеглем по ширине помещения (`labels.ts`), у двери в верхней стене —
    внизу помещения.
  - Запись пола проигрывается на каждом кадре, пока кто-то идёт, поэтому она из
    прямоугольников, а не путей. Сначала пол был путями по цвету, и прототип П2 в веб-сборке
    просел с 39 до 16 кадров в секунду; на прямоугольниках — снова 39.
  - Часть 23 (0.0.38): лампа над дверью и свет ЭКГ и рентгена горят, пока человек на карте
    там, где с ним что-то делают. `Walkers` отдаёт вместе с путём, с какого и до какого
    времени кто стоит под лампой; ворклет решает по часам карты. На ×4 часы смены обгоняют
    идущих, поэтому свет — по карте, а не по смене. Из смены (`src/state/roomSigns.ts`) — только
    то, у чего нет человека на карте: анализы лаборатории, очередь и «нет персонала» на
    значках.
- **Камера** — пан и масштаб жестами (`react-native-gesture-handler`), матрица —
  общее значение Reanimated.
- **Касание** переводится обратной матрицей в клетку сетки, клетка — в помещение или
  человека. Считается на JS-потоке по данным движка.
- **Когда на карте ничего не движется, кадры не рисуются.**
- **Бюджет**: 60 кадров/с на современном телефоне при 60 людях и 600 предметах и ни
  одного подвисания дольше 100 мс (NFR-PRF-1); слабые телефоны — без гарантий.
  Проверяется первым прототипом ([`specs/2026-09-spikes.md`](specs/2026-09-spikes.md));
  если не выходит — упрощённый план без анимации людей.
- **Сейчас (смена 0.0.14, план — с 0.0.19)** карта — одна амбулатория над очередью, во всю
  ширину экрана, без камеры. План строит движок стройки (`src/engine/hospital/build.ts`) из
  записи каталога `preset.clinic` — теми же командами, что будут у игрока в песочнице; сетка,
  предметы и места людей выводятся из помещений чистой функцией `planOf`, а
  `src/engine/hospital/clinic.ts` превращает план в места карты смены: персонал, куда встаёт
  пациент, стулья зала и скамьи коридора.
- **Смена в своей больнице (0.0.21)** — движок смены берёт больницу из состояния (в
  практике — готовую амбулаторию каталога со штатом навыка 3): `hospitalCtx` — план,
  штат, какие помещения работают, стулья, есть ли доврачебный кабинет; строится один раз на
  план и штат (они меняются только между сменами, новыми объектами). Карта смены рисует
  план без пустой улицы вокруг (`cropPlan`) — своя больница во всю ширину экрана, как
  практика; новый план — новые ходоки. Касание мимо людей — помещение под пальцем (0.0.23,
  только своя больница): что это, работает ли, кто в нём — из `hospitalCtx` раз на день, что
  там сейчас — из смены при каждом ходе часов (`roomsOf` в `src/state/session.ts`).
- **Кампания (0.0.24)** — та же смена, что в песочнице (больница, касса, штат), в режиме
  `campaign` и со своим `campaign`: глава, день её начала, выполненные задания и письма.
  `src/engine/campaign/campaign.ts` выводит ход задания из итогов дней главы и больницы;
  вечером движок смены зовёт `campaignEvening` — что выполнено, какие письма пришли, конец
  главы. Три карьеры — три слота сохранения `campaign-1`…`campaign-3`; в сессии —
  `loadShift('campaign', n)` и `startCampaign`; вид главы — `campaignView` (письма, задания
  с ходом словами), экран карьер — `src/app/campaign/index.tsx`, глава между сменами — над
  своей больницей (`src/ui/campaign.tsx`).
- **«Смена» (0.0.28)** — режим `single` со своим слотом: `newSingle` — день 1 практики с
  больницей из записи готовой (`preset.village` — со своим штатом) или копией своей из
  песочницы, без кассы. Карта смены — план этой больницы, как у своей. Итог — `singleResult`
  в `src/state/single.ts`; при закрытии дня лучший результат по больнице — в профиль
  (`recordSingle`); список больниц с причинами — `singleVenues` в сессии.
- **«Случай дня» (0.0.27)** — `src/state/daily.ts`: зерно — дата и номер базы
  (`daily:ГГГГММДД:база`), время года — по месяцу даты; приём — тот же приём одного
  пациента, что у прототипа П4: `createVisit` в `src/state/visit.ts` даёт каждому свой
  экземпляр. После «Завершить приём» первая попытка дня пишется в профиль
  (`recordDaily`); экраны — `src/app/daily/` над общими экранами приёма.
- **Достижения (0.0.26)** — `src/engine/career/achievements.ts`: из счётчиков профиля и
  того, что есть сейчас (какие помещения своей больницы работали в закрытый день, какие
  главы выполнены), — какие достижения получены. Профиль зовёт её при записи закрытого
  приёма (`recordCases`) и закрытого дня (`recordDay` из `closeDay` сессии) и ставит дату;
  вид приёма и итогов дня берёт названия по ключу приёма или дня.
- **Первая смена главы (0.0.25)** — план первого дня главы берёт болезни из `tutorial` для
  первых пришедших (`typicalPatient`: человек из той же ветви зерна, у кого болезнь обычна).
  Подсказки наставника — не движок: `src/state/tips.ts` выбирает одну, что к месту, по
  состоянию приёма (экран, вопросы, осмотр, решение) и по показанным; показанные и «Без
  подсказок» — в `campaign.tips` карьеры, как «прочитано» у письма. Лист — `MentorTip`
  поверх карты пациента, решения и итога смены; закрыли — следующая ждёт следующего
  действия врача.
- **Касса песочницы (0.0.22)** — `src/engine/economy/economy.ts`: чистые функции без
  состояния. Движок смены зовёт их в трёх местах: при плане дня (плательщик пациента из
  ветви зерна `payer:<номер>`, поток от репутации), при обследовании (показано ли — по тому,
  что известно сейчас; расходники в кассу дня) и при закрытии приёма (оплата после
  экспертизы — в кассу дня и в запись пациента); вечером `settle` добавляет зарплаты,
  содержание и процент на долг, меняет кассу и репутацию и кладёт всё в итоги дня. Строки
  для экрана — `src/state/sandboxView.ts` (`cashView`, `paymentText`). Практика этих вызовов
  не делает: у неё нет `economy`, и её смена — как прежде.
- **Экран стройки (песочница, 0.0.20)** — `src/render/map/BuildMap.tsx`: тот же пол,
  стены и атлас предметов, плюс сетка клеток и камера — сдвиг и масштаб в общих значениях
  Reanimated (`get`/`set`, как требует React Compiler), жесты двигают их на UI-потоке;
  подписи помещений — слой RN с той же матрицей. На JS уходят только клетки: куда тянут
  призрак помещения, где прошла кисть коридора (копится на UI-потоке и рисуется путём Skia,
  на JS — разом, когда палец отпустили), чего коснулись. **Кто где и что делает —
  выводится из состояния смены** (`src/state/clinicMap.ts`) и приходит в «виде» смены, а не
  хранится: формат сохранения прежний, и после загрузки карта та же. **Кто куда идёт** —
  `Walkers` (`src/render/map/walkers.ts`, без React и Skia, проверяется в Bun). Места —
  остановки маршрута: смена на ×4 меняет их быстрее, чем человек доходит, поэтому у стойки,
  у стола медсестры и у аппарата он хотя бы немного стоит, стул или скамью, до которых не
  дошёл, заменяет следующее место, а в кабинет по вызову идёт сразу и вдвое быстрее. Новый
  путь — A* от клетки, к которой человек шёл, со сдвигом времени, так что он не прыгает и не
  пятится; стоянка — повтор точки пути. На UI-поток уходят все пути одним массивом и на
  каждого — смещение, число точек, время выхода, скорость и «исчезнуть у цели»; позицию на
  кадре считает ворклет от часов карты. Люди идут 4 клетки в секунду настоящего времени на
  любой скорости смены. Часы карты стоят, пока экран не на виду и пока все дошли, — тогда
  общие значения не меняются и Skia кадров не рисует. **Касание** — ближайший не дальше
  клетки, любой: он обведён, под картой — кто это и что делает; ждущего приёма можно
  пригласить. Приглашённый идёт в кабинет, и карта пациента открывается, когда он вошёл
  (карта знает время прихода по своим часам).

## 7. Экраны, навигация, «правда» и «вид»

- **Навигация — Expo Router** (ADR [0003](adr/0003-expo-router.md)): экранов около двадцати,
  энциклопедия ссылается сама на себя, в веб-сборке у каждого экрана свой адрес — сценарии
  Playwright открывают нужный экран сразу.
- **Живая партия не в параметрах маршрута.** Она живёт в `src/state/session.ts`
  (одна на приложение); в параметрах — только идентификаторы (`/game/patient/[id]`).
- **Подписка.** Состояние меняется движком на месте (ради скорости), а у каждого среза
  («очередь», «карта пациента N», «деньги», «карта больницы») — счётчик версии. Хук
  `useSession(selector)` работает через `useSyncExternalStore` и перерисовывает экран,
  только когда изменилась версия его среза.
- **Правда недоступна интерфейсу.** Экраны игры получают «вид» пациента из
  `src/state/caseView.ts`: сказанное, открытые признаки, результаты, назначения,
  подсказки. Истинные состояния, скрытые параметры и нераскрытые признаки туда не
  попадают. Импорт генератора, обследований и политики из `src/app/` и `src/ui/` запрещён
  правилом линтера (`no-restricted-imports`); правду видит только разбор закрытого случая
  через `engine/med/review.ts`.
- **Сейчас (смена 0.0.7)** у смены один счётчик версии: `useShift()` — очередь, часы,
  итоги дня; `useShiftCase()` — приём в кабинете или итог закрытого случая. Вид
  собирается лениво и кешируется по версии. Экраны карты пациента, решения и итога —
  общие для прототипа П4 и смены (`src/ui/case`): вид и действия приходят снаружи.
- **Свой диалог вместо `Alert`**, как в «Вотчине»: системный `Alert` ничего не делает
  в веб-сборке, на которой идут сценарии.
- **Вид — из темы на сейчас** (spec 2026-09-own-look, часть 24). Две темы — данные в
  `src/ui/palette.ts`: цвета, шрифты, форма (штамп, закладки, двойная черта, линовка).
  `useTheme()` в `src/ui/theme.ts` берёт выбор из настроек, а «как в телефоне» — из
  `useColorScheme()`. Стили экранов — `makeStyles(t => …)`: лист на тему собирается один раз,
  при смене темы экраны перерисовываются без перезапуска. Листов стилей с цветами на уровне
  модуля в `src/app` и `src/ui` нет — их сторожит тест. План больницы, портреты и снимки
  (`src/render`) не перекрашиваются: план — светлый чертёж в обеих темах, выделенное на нём —
  цвет темы `mark`, тёмный и в «Мониторе».
- **Шрифты — в сборке.** TTF и лицензии OFL — в `assets/fonts`. На Android плагин
  `expo-font` (app.json) собирает начертания в семейства, и `fontFamily` с `fontWeight`
  работают как с системным шрифтом; в веб-сборке те же файлы подключает `src/ui/fonts.web.ts`
  правилами `@font-face`. Сеть не нужна.

## 8. Сохранения, профиль, отчёт об ошибке

Форматы — [`07-data-model.md`](07-data-model.md).

- **Хранилище** — своя обёртка `src/state/storage.ts`: на телефоне файлы
  (`expo-file-system`), в веб-сборке — `localStorage` (`storage.web.ts`). Запись
  атомарная: во временный файл, затем переименование.
- **Слоты.** Три слота кампании плюс по одному на песочницу и незаконченную смену.
  У каждого — текущий файл и две предыдущие копии; испорченный текущий заменяется
  предыдущей копией с сообщением игроку. Настройки (`src/state/settings.ts`, 0.0.11) —
  такой же слот `settings`: запись по касанию, чтение поле за полем.
- **Когда пишется:** конец каждого игрового часа на карте, уход приложения в фон,
  конец дня, выход в меню. Сериализация — на JS-потоке порциями, запись — фоном.
  Сейчас (смена) ещё — закрытый случай и «отпустить ждать результатов»; снимок —
  одним `JSON.stringify` (≈ 270 КБ за неделю практики, 3 мс в Bun). Запись — следующей
  задачей после касания, несколько просьб подряд — одна запись; уходя в фон — сразу.
  Копии сдвигаются переименованием, а не копированием (0.0.8: копирование двух копий на
  телефоне стоило дороже самой записи); прерванную между сдвигом и заменой запись
  читаем из временного файла. Миграций пока нет (схема 1): сохранение, которое ссылается
  на то, чего нет в базе, не читается. С 0.0.20 живая партия одна, но слотов два:
  практика (`shift`) и песочница (`sandbox`); у снимка свой режим (`meta.mode`), и запись
  идёт в его слот, даже если партия успела смениться. «Продолжить» в меню — последняя
  записанная (`savedGames`).
- **Миграции.** В сохранении — `schemaVersion` и `contentVersion`. Цепочка
  `src/state/migrations/NNNN-*.ts` поднимает старое сохранение до текущей схемы.
  Изменение базы сохранений не ломает: у пациента в состоянии уже лежат его
  реализованные признаки и правда, а идентификаторы вечные (ADR 0011).
- **Профиль** (статистика, специальности, достижения, энциклопедия, архив) — отдельный
  файл, общий для всех слотов. Полные записи случаев — для последних 200, остальные
  сжаты до итогов. Сейчас (0.0.15, `src/state/profile.ts`) — слот `profile`, как у
  настроек: имя и пол врача, итоги практики, «встречалось в практике» и архив последних 50
  приёмов; с 0.0.26 — достижения с датой и счётчики к ним. Закрытый приём смена отдаёт в профиль один раз (ключ — зерно смены и номер
  пациента): после сбоя и при перечитанном сохранении ничего не удваивается. Пока профиль
  не прочитан с диска, приёмы ждут в памяти — запись не затирает файл. Разбор приёма из
  архива строится тем же `engine/reviewFor`, что в смене: из записи пациента и зерна.
- **Отчёт об ошибке** (как в «Вотчине» 2.10): игрок нажимает «Сообщить об ошибке» и
  видит весь текст: версия игры и базы, модель телефона и Android, журнал последних
  сбоев, зерно дня и журнал команд за день (сжатый). Отправляет он сам — через
  «Поделиться» в почту или мессенджер; сама игра ничего не передаёт. По зерну и журналу
  день переигрывается в тестах. Сейчас (0.0.17): `src/state/report.ts` собирает текст,
  `src/state/errors.ts` держит пять последних сбоев (глобальный обработчик React Native,
  слот `errors`), «Поделиться» — встроенный `Share` React Native; журнал дня — одной
  строкой JSON, без сжатия.

## 9. Тексты и языки

- **Интерфейс** — `src/i18n/sections/*`, как в «Вотчине»: словарь каждого языка
  объявлен с типом русского, и неполный перевод не собирается. Пока есть только
  русский: английский — по спросу (`02-requirements.md` §7), добавляется целиком, когда
  понадобится. Тест падает на кириллице в строках кода вне `src/i18n` и `content/`.
- **База** — тексты в YAML (`ru` обязателен, `en` — по готовности), собираются вместе
  с базой.
- **Род и число.** Пациент и врач бывают мужчиной и женщиной, поэтому шаблоны текстов
  знают род: `«{заболел|заболела} {n} {день|дня|дней} назад»`. Разбор шаблонов —
  `src/i18n/template.ts`, склонения числительных — `plural.ts` (перенос из «Вотчины»).
- **Речь пациента** собирается из шаблонов признаков: несколько вариантов на признак,
  выбор — из ветви зерна пациента, поправки по черте характера («тревожный» говорит
  ярче).
- Язык — `expo-localization` при первом запуске, дальше — настройка.

## 10. Звук и вибрация

- `expo-audio` (`expo-av` удалён из Expo SDK 55). Короткие звуки загружаются при
  старте в пул проигрывателей; фон и музыка — зацикленные потоки.
- Четыре канала с раздельной громкостью: интерфейс, события, фон, музыка.
- Звук — следствие событий движка: сессия переводит «готов результат», «пришёл
  красный» в звук и вибрацию (`expo-haptics`) по настройкам. В движке звуков нет.
- Файлы звуков — `assets/audio/`, лицензии — `assets/audio/LICENSES.md` (только CC0 или
  свои записи, ADR 0008). Касание, «готов результат» и «срочный» синтезирует
  `tools/audio/gen.ts`; приход пациента и фон амбулатории собирает `tools/audio/clinic.ts`
  из звуков набора Kenney (CC0) и своего гула вентиляции. Файлы — готовые WAV (моно, 16 бит,
  22 050 Гц), пересобирать их для сборки игры не нужно.
- Фон — петля 40 с, пока на виду экран смены (`setAmbient` в `src/audio/sounds.ts`):
  выключен в настройках, звук на нуле или игра свёрнута — молчит; в вебе-стенде фона нет.
  Дверь при приходе пациента — не чаще раза в 6 с.

## 11. Изображения, нарисованные кодом

Решение — ADR [0013](adr/0013-procedural-imaging.md). Все функции — чистые: (признаки
случая, параметры, зерно) → рисунок Skia.

| Что | Как |
|-----|-----|
| рентген грудной клетки | шаблон (рёбра, тень сердца, купола диафрагмы, корни) с размытием и шумом; поверх — генераторы находок: инфильтрат в зоне стороны и доли, выпот с мениском, пневмоторакс, увеличение тени сердца |
| рентген костей | кости — контурами через опорные точки: корковый слой вдоль диафиза, губчатое вещество, замыкательные пластинки; линия перелома делит кость на два отломка, смещённый — со сдвигом и поворотом, за ним — кости, которые за ним следуют |
| ЭКГ | синтез: ритм задаёт интервалы RR, морфология — сумма «горбов» P, QRS, T по отведениям; модификаторы — подъём и депрессия ST, инверсия T, широкий QRS, отсутствие P и волны f при фибрилляции, пила при трепетании. Лента на миллиметровке, 25 мм/с |
| КТ и МРТ головы | стилизованный срез; очаги ишемии и кровоизлияния в бассейне по параметрам случая |
| УЗИ | сектор с зернистостью; камни с акустической тенью, свободная жидкость, расширение лоханки |
| портреты | слои (лицо, волосы, возрастные черты, очки, одежда), выбор и цвета — из зерна человека |

Изображение сопровождается текстовым протоколом из шаблонов признаков, поэтому
игра остаётся проходимой и без умения читать снимки. Сейчас (0.0.10) в карте пациента
рисуются рентген грудной клетки и ЭКГ: вид приёма (`src/state/caseView.ts`, `ResultImage`)
отдаёт то, что показало обследование, — сторону инфильтрата, повышенную воздушность,
подъём или депрессию ST, высокий R, частоту по пульсу, — а не правду: ложный результат
нарисован так же, как настоящий. С 0.0.34 — срез головы на КТ и МРТ (`src/render/ct/`,
спецификация [`specs/2026-09-ct-mri-ultrasound.md`](specs/2026-09-ct-mri-ultrasound.md)):
пока прототипами в «Проверках» — в базе нет КТ и МРТ. Рисовальщик болезней не знает: очаг
задан параметрами (плотность, форма, сторона, часть полушария, размер, смещение), а что какой
признак значит, запишут признаки базы по источникам. Геометрия — чистые функции
(`ct/geometry.ts`), рисунок — одна запись в `SkPicture` (`ct/head.ts`). Рисунки проверяются в
тестах без экрана: та же Skia через CanvasKit (`tools/imaging/headless.ts`), яркость в нужных
точках и одинаковые байты при том же зерне. С 0.0.35 — сектор УЗИ (`src/render/us/`): выпуклый
датчик, зернистость поверх тканей, жидкость чёрная и за ней светлее, за плотной точкой — тень
по лучу; печень с желчным пузырём и почка под печенью. С 0.0.53 — рентген костей
(`src/render/xray/boneGeometry.ts`, помощники — `boneShapes.ts`, рисунок — `bones.ts`, spec
[`specs/2026-09-chapter-2.md`](specs/2026-09-chapter-2.md), часть 31): запястье и голеностоп — две
проекции на одной плёнке, стопа, тазобедренный сустав, ключица и рёбра — одна. Перелом задан местом
и смещением; линия делит кость на неподвижный и смещённый отломок — две записи с обрезкой, между
ними узкий просвет; снимок левой стороны — те же панели зеркально. С 0.0.54 снимок кости — в карте
пациента: `caseView` собирает его из того, что показал снимок запястья или голеностопа (линия
перелома, смещение, признаки нестабильности), сторона — из жалобы; рисует `XrayBone` в
`ResultPicture`, как снимки груди и живота.

## 12. Ограничения, о которых стоит помнить

- **Expo меняется с каждой версией.** Перед любым кодом с API Expo — версионная
  документация (`AGENTS.md`), а не память.
- **React Compiler включён.** Нельзя писать в ref во время отрисовки и вызывать
  `setState` синхронно в эффекте — линтер остановит сборку. И компилятор запоминает
  вызовы по тождеству аргументов: `f(db, shiftState())` с живым состоянием движка —
  тот же объект после любых перемен, и результат не пересчитается (так замерла карта
  при сборке 0.0.13). Экран берёт данные из «вида», который пересобирается по версии
  (`ShiftView`), а не из живого состояния.
- **Нативные модули требуют пересборки.** `android/` не хранится в репозитории (её
  создаёт `expo prebuild` в CI), поэтому новая библиотека с нативным кодом проверяется
  только полной сборкой APK.
- **Skia в вебе** работает через CanvasKit (WASM, несколько мегабайт): файл
  `canvaskit.wasm` кладётся в `public/` скриптом `setup-skia-web` при каждом обновлении
  библиотеки. Веб-сборка — стенд для сценариев, не продукт (ADR 0003). Каждый холст в вебе
  держит свой контекст WebGL, а их у страницы не больше 16: лишние теряются, и холст пустеет.
  Поэтому на экране, где рисунков много (снимки в «Проверках»), они рисуются с `still`
  (`__destroyWebGLContextAfterRender`): один раз, и контекст отпускается (с 0.0.34; на
  телефоне признак не действует). По умолчанию выключено: спрятанный холст — экран ниже в
  стеке, ширина 0 — так перерисовать нельзя, CanvasKit роняет `drawImage`.
- **Сети нет.** Никакая библиотека не должна требовать `INTERNET`; итоговые разрешения
  проверяет CI (ADR 0006, ADR 0015).
