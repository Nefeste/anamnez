# Как проверяется

Проверки идут по возрастанию цены: сначала то, что занимает секунды. Всё, что можно
проверить без телефона, проверяется без телефона — движок для этого и сделан чистым.
Пока кода нет, документ — план; команды и файлы появятся вместе с кодом.

## 1. Типы и линтер

```bash
npx tsc --noEmit -p .        # приложение
npx tsc --noEmit -p tools    # тесты, сборка базы, симулятор (Bun)
npm run lint                 # ни ошибок, ни предупреждений
```

Линтер, кроме правил Expo и React Compiler, держит границы слоёв:

- `src/engine/**` не импортирует React, React Native, Expo и `src/state`;
- `src/app/**`, `src/ui/**` и `src/render/**` не импортируют правду пациента (генератор,
  обследования, политику) — только вид из `src/state` и команды; исключение — разбор
  закрытого случая через `engine/med/review`;
- в `src/engine/**` запрещены `Math.random`, `Date.now`, `new Date()` и
  `Math.exp|log|pow|sin|cos` (ADR [0004](adr/0004-deterministic-engine.md)).

Всё это и тесты идут в CI на каждый PR (сценарии в браузере — после мёржа, §4).

### Золотые случаи

Как «золотые партии» «Вотчины»: набор зёрен × отделений × сложностей, для каждого —
сгенерированный пациент (правда), результаты фиксированной цепочки обследований и итог
«виртуального врача». Лежат в `tools/test/fixtures/golden-cases.json`.

- Любое изменение генератора, модели или базы, которое меняет пациента, роняет тест.
- Пересоздание — только сознательно (`ANAMNEZ_GOLDEN=write`) и в том же коммите, где
  изменение базы или модели; в описании коммита — почему случаи изменились.
- Это не запрет менять базу, а гарантия, что изменение **заметили**.

### Переигрывание дня

Отчёт об ошибке несёт зерно дня и журнал команд (`06-architecture.md` §8). Тест
`replay.test.ts` берёт такие журналы из `fixtures/replays/` и переигрывает день: состояние
в конце должно совпасть с записанным хешем. Каждая исправленная ошибка из отчёта
становится таким тестом.

## 3. Медицинская база

```bash
npm run content   # сборка и валидатор
npm run doctor    # «виртуальный врач»: короткий прогон; --full — все отделения
```

Правила валидатора, матрица различимости и пороги «виртуального врача» — в
[`05-content.md`](05-content.md) §6. Коротко о «виртуальном враче»:

- три стратегии — разумный, ленивый, «всё подряд» — по тысячам сгенерированных
  пациентов на отделение;
- пороги: разумный — точность до группы ≥ 90 % и сбалансированная ≥ 85 %; ленивый —
  сбалансированная хотя бы на 25 п. п. ниже; «всё подряд» дороже разумного не меньше
  чем в 3 раза (определения — `05-content.md` §6);
- отчёт по каждой болезни: точность, цена, время, самые частые путаницы — артефактом
  CI (`doctor.yml`), и он же — карта сложности для заданий кампании;
- с 0.0.32 — нанятый врач по навыку 1–5 (spec 2026-09-hired-doctors): тот же разумный с
  порогами навыка из `economy.yaml` на первой тысяче тех же пациентов, с теми же
  результатами обследований; навык 5 — сам разумный. Пороги: точность растёт с навыком, у
  навыка 5 — не ниже 88 %, у навыка 1 — выше ленивого и ниже навыка 3, сбалансированная у
  навыков 1 и 5 расходится не меньше чем на 8 п. п.

Экономика — `npm run economy-sim` (с 0.0.22): песочница с готовой амбулатории живёт 30
дней с разными врачами — те же зёрна, обследования только те, что больница может сделать,
диагноз по тому, что пришло в смене; разумный доназначает, если не уверен, и подтверждает
диагноз, если может. Критерии — в спеке своей больницы (приёмка 4): у разумного касса не
в минусе, прибыль — от четверти до всей цены амбулатории; «всё подряд» зарабатывает
меньше; у ленивого репутация ниже 40; без лаборатории и рентгена — меньше, чем с ними. Для
сведения — самая простая амбулатория и «всё платное сразу, до расспроса». С 0.0.32 — ещё
разумный с нанятым терапевтом навыка 3 или 1 во втором кабинете (ординаторская, коридор
справа от амбулатории): с терапевтом навыка 3 принимают больше и зарабатывают больше, чем
без него, а с навыком 1 — меньше и с репутацией ниже (spec 2026-09-hired-doctors, приёмка 2). Отчёт — в
описании коммита, который меняет баланс; `--json` — для проверки в CI. Правила кассы —
`tools/test/economy.test.ts`; для кампании — скриптовая больница главы, деньги в конце —
в заданном коридоре (не банкрот, не миллионер).

Кампания (с 0.0.24) — `tools/test/campaign.test.ts`: задания по заданным историям дней,
письма после дня, при задании и в конце главы, ограничение стройки главы, три независимые
карьеры; сценарий Playwright — новая карьера, письмо наставника, смена в главе,
«Продолжить» — карьера. Первая смена с наставником (с 0.0.25) — `tools/test/tips.test.ts`:
первые трое пришедших в главе — заданные болезни, остальные и следующие дни — как обычно;
подсказки по одной и к месту, каждая один раз за карьеру, «Без подсказок», вне первой смены
главы и вне кампании их нет; валидатор — `content.test.ts` («кампания»). Сценарий

условие каждого вида, новые — только ещё не полученные и по порядку, приём и день — один
раз, дата и ключ переживают перезапуск, строка на итоге приёма и в итогах дня; валидатор —
`content.test.ts` («достижения»); сценарий Playwright — строка на итоге первого приёма и
«Первый пациент» в профиле. «Случай дня» (с 0.0.27) — `tools/test/daily.test.ts`: те же дата
и база — тот же пациент, другие — другой; 30 дней через границу месяца; первая попытка — в
профиль, повтор её не меняет и называет; «семь случаев дня»; сыгранное с другой базой — с её
номером. Сценарий Playwright — список, приём, разбор, отметка «Сыгран» у сегодняшнего дня.
«Смена» (с 0.0.28) — `tools/test/single.test.ts`: в амбулатории практики — те же пациенты,
что в практике, своя больница — копия; итог по категориям; общая не выше точности и не больше
чем на ступень выше худшей категории; лучший результат; какие больницы доступны и почему нет.
Сценарий Playwright — список больниц, «Продолжить» — смена, закрытый день, итог и «Лучший
результат в этой больнице». Формулу итога проверяли на стратегиях «виртуального врача».

Темп смены — `npm run shift-sim`: разумный врач (обследования из политики, анализы и
снимки — «отпустить ждать результатов») и терпеливый (ждёт каждый результат в кабинете)
на одних и тех же сменах. Ориентир первой смены: разумный принимает не меньше 90 %
пришедших, терпеливый заметно меньше — иначе очередь ничему не учит.

## 4. Сценарии в браузере

Веб-сборка — стенд, как в «Вотчине»: Playwright по сборке `expo export --platform web`
(`tools/e2e/*.ts`). Сеть в сценариях не нужна, сервера нет.

| Сценарий | Что проходит |
|----------|--------------|
| `first-shift.ts` | обучение главы 1: ОРВИ, ангина, цистит — от очереди до разбора |
| `pneumonia.ts` | фиксированное зерно: опрос, аускультация, рентген, диагноз, лечение, исход через день |
| `red-flag.ts` | боль в груди: ЭКГ за 10 минут, перевод; пропуск — повторное обращение хуже |
| `build.ts` | стройка лаборатории, требования, отмена, цена |
| `encyclopedia.ts` | переходы по ссылкам, поиск, оговорка вверху |
| `save.ts` | сохранение, перезапуск, продолжение с того же места; испорченный файл → предыдущая копия |
| `settings.ts` | громкости, подсказки, мягкий режим, размер текста |

Ожидаемые тексты в сценариях — русские, дословно; меняется текст — меняется сценарий.

Сейчас все проверки — в одном `tools/e2e/smoke.ts`: оговорка первого запуска (до меню,
один раз), имя и пол врача (имя подставлено, смена пола его меняет), меню, сложность при
начале практики (по умолчанию «Студент», в карте — «Похоже на»), размер текста («Крупный» —
шрифт в 1,3 раза больше), отчёт об ошибке (описание первой строкой, номер сборки), настройки (сохраняются после перезапуска), «Об игре» (версия, оговорка,
почта, источники базы), энциклопедия (оговорка вверху, раздел → статья → ссылка, поиск;
«Подробнее» из «Что это?» и статья из разбора — и «назад» к приёму); прототипы этапа 1 (в карте приёма — рентген снимком, а не только
строками) и смена (карта амбулатории с ждущими в зале; касание медсестры — кто она, касание севшего в зале — кто он и «Пригласить»; у вашего кабинета — значок «Ждут: N» (с 0.0.38); ответ на вопрос — под самим вопросом (с 0.0.38); приглашённый доходит до кабинета, и тогда открывается его карта; часы, приём, «отпустить ждать результатов», итог, «Продолжить» и
«Начать заново» в меню; профиль после приёма — «Принято: 1», приём в архиве открывается
разбором, в статье болезни — «Встречалось в вашей практике: 1 раз»; конец дня — из сохранения, записанного движком, — итоги, разбор из
итогов, следующий день). Перенос на другой телефон (с 0.0.29): «Сохранить в файл» —
скачивание; в чистом браузере «Открыть файл» — что в файле, «Заменить» — и сразу меню со
своим врачом. Нанятый врач (с 0.0.32): песочница с терапевтом во втором кабинете — в итогах
дня «вами X, врачами Y» и его строка, в «Персонале» он работает в «кабинете врача № 2»; с
0.0.33 посреди дня — «У врачей», его приём только для чтения, «Забрать себе» — и карта ваша, а
в итогах — разбор его приёма («Приём вела терапевт …» или «вёл»). В конце — маленький экран 360 × 640 (с 0.0.28): длинный лист
поверх экрана — выбор помещения — прокручивается, первый тип и «Отмена» видны, последний тип
выбирается прокруткой листа.

В CI сценарий идёт после мёржа в `main`, а не на каждый PR: минуты Actions бережём
(решение владельца, 26.09.2026). Он — ворота релиза: не прошёл — APK не выкладывается.
Поэтому перед пушем сценарий гоняется локально (`npm run export:web && npm run e2e`).

## 5. На телефоне

Веб-сборка не проверяет нативное: Skia на GPU телефона, звук, вибрацию, файлы,
автобэкап, подпись. Поэтому к каждому выпуску:

- **современный телефон** (Android 16, телефон владельца): смена на ×4 с полной
  больницей главы — 60 кадров по счётчику отладочной сборки, ни одного подвисания
  дольше 100 мс; запуск до меню до 3 с; нагрев и расход батареи за смену записываются;
- старый или слабый телефон — по возможности, для сведения: гарантий нет (NFR-PRF-1);
- звук по всем четырём каналам, вибрация, автопауза;
- установка поверх прошлой версии (тот же ключ) — сохранения на месте;
- перенос через файл: сохранить на одном телефоне, открыть на другом.

**Доступность (NFR-ACC-1), ревью экранов.** 28.09.2026 (0.0.29) основные экраны пройдены
на веб-сборке: на 360 × 640 с «Крупным» текстом (1,3) — ничего не вылезает за край, длинные
листы прокручиваются; на 412 × 915 — всё нажимаемое не меньше 48 dp. Кнопки — 48 и выше,
«?» («Что это?») — 36 с полем касания 8 (52), вкладки — 40 с полем 4 сверху и снизу (48);
стрелка «Назад» — системная шапка Android. Переключатель в строке настроек для чтения с
экрана — часть строки, а не отдельный элемент. Срочность — значком и словом («‼ срочно»).
Размер поля касания веб-сборка не показывает: его проверяет телефон.

## 6. Снимки для магазинов и снимки кодом

`tools/store/render.ts` (`npm run store`, после `npm run export:web`) — как в «Вотчине»:
Playwright ставит игру в нужное состояние и снимает экраны 1080 × 1920 для телефона, с
подписями, шрифтом Roboto, как на Android. Состояния смены пишет движок
(`tools/store/states.ts`: зерно подбирается по условию — очередь со срочным, пневмония на
снимке, инфаркт на ЭКГ, итоги третьего дня), поэтому снимки воспроизводимы. Тем же
инструментом рисуются иконка (`tools/store/art.ts`) и графика магазина и сайта. Снимки для
планшетов и английские — когда понадобятся.

Снимки, нарисованные кодом (ADR 0013), смотрятся и без веб-сборки: `npm run imaging` рисует
варианты «Проверок» в PNG (`tools/imaging/out/`) той же Skia через CanvasKit, без экрана
(`tools/imaging/headless.ts`, с 0.0.34); с 0.0.37 — ещё план амбулатории практики с людьми
(`map-clinic.png`) и атлас карты целиком (`map-atlas.png`). Тем же путём снимки проверяются в
тестах (`imaging.test.ts`, `mapdraw.test.ts`): где светло и где темно, то же зерно — те же
байты.

Тест `store.test.ts` проверяет длины полей карточки (название ≤ 30, краткое ≤ 80,
полное ≤ 4000), оговорку, отсутствие чужих игр, брендов лекарств и обещаний медицинского
приложения в `store/`, подписи снимков, размеры картинок и иконку без прозрачности.
Торговые названия лекарств (`tools/content/brands.ts`) не пропускают и в других местах:
в базе — валидатор при сборке, в словаре интерфейса — `i18n.test.ts`.
